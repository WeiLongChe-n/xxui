# 介绍

Vela UI 是一套面向移动端的 Vue 3 组件库，设计目标是 **轻量、可定制、开箱即用**。它参考了业界成熟移动组件库的交互规范，同时在主题系统上做了更彻底的抽象：所有视觉表现都由 CSS 变量与色相令牌驱动，**换肤不需要重新编译，也不会产生额外的样式体积**。

## 特性

- **55 个组件**：覆盖基础展示、表单、反馈、导航、布局五大类，满足绝大多数中后台与 C 端移动页面。
- **12 种预设主题**：6 套品牌配色 × 明暗双模式，支持运行时切换、持久化与跟随系统。
- **TypeScript 编写**：组件 Props、事件、命令式 API 均有完整类型，随包发布 `d.ts`。
- **移动端细节**：0.5px 细边框、安全区适配、滚动穿透处理、手势拖拽、懒渲染。
- **两套调用方式**：既可以用 `<vl-toast>` 组件，也可以用 `Toast.success()` 函数式调用。
- **零运行时依赖**：除 `vue` 外无任何第三方运行时依赖，样式使用 SCSS 编译为纯 CSS。

## 文档站里的交互预览

每个组件页右侧都有一个**可以直接点的手机预览**，不是截图，是真实渲染的组件。

整页所有示例共用这一个预览盒：左侧只放说明和代码，滚动到哪个示例、或者点击哪张卡片，右侧就切换到对应的交互。这样一屏里始终只有一个手机框，不会出现一长串重复的设备外壳。

预览运行在独立的 iframe 沙箱里：组件库样式被注入沙箱内部，文档站的样式不会带进去，两者互不影响，也不会互相污染。所以你在预览里看到的，就是这些组件被装进真实项目后的样子。

预览上方的工具条只作用于沙箱内部：

| 控件 | 作用 |
| --- | --- |
| 六个色点 | 切换预览内的品牌配色（默认 / 海松青 / 翡翠绿 / 紫罗兰 / 落日橘 / 石墨灰） |
| 深色 / 浅色 | 切换预览内的明暗模式，不影响文档站本身 |
| 重置 | 重新挂载当前示例，把弹窗、开关等状态复位 |
| 全屏 | 放大预览，`Esc` 退出 |

视口窄于 1280px 时会自动回落到「示例卡片内嵌手机框」，交互能力完全一致。

Toast、Dialog、ActionSheet、Popup、Overlay 这些弹层组件的挂载目标会被自动指向沙箱内部，弹层只覆盖手机屏幕，不会盖住文档页。

## 环境要求

| 环境 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | `>= 18`（推荐 20 / 22 LTS） | 仅开发、构建与文档站需要；运行时不需要 Node |
| 包管理器 | npm `>= 9`、pnpm `>= 8`、yarn `>= 1.22` | 任选其一 |
| Vue | `>= 3.3` | 组件使用 `<script setup>` 与 `defineOptions` |
| 浏览器 | iOS Safari 12+ / Chrome 80+ | 见下方浏览器支持 |

::: tip 运行时零依赖
`@vela/mobile` 的 `dependencies` 为空，`vue` 作为 peerDependency 由宿主应用提供，因此打包产物不会引入额外运行时。
:::

## 浏览器支持

| 浏览器 | 版本 |
| --- | --- |
| iOS Safari | 12+ |
| Android Chrome / 微信内置浏览器 | 80+ |
| Chrome / Edge | 80+ |
| Firefox | 78+ |

组件内部使用了 `IntersectionObserver`、`ResizeObserver`、CSS 变量、`backdrop-filter`（Toast 毛玻璃，可降级）等现代特性，在极老旧的 WebView 中会有视觉降级，但功能仍可用。

## 目录结构

```
vela-ui/
├── packages/mobile-ui/        # 组件库源码
│   ├── src/
│   │   ├── components/        # 55 个组件，按目录拆分
│   │   ├── styles/            # 主题变量 / mixin / 过渡动效
│   │   ├── theme/             # 主题运行时（切换、持久化）
│   │   ├── utils/             # BEM、手势、滚动锁定等工具
│   │   └── index.ts           # 库入口
│   ├── vite.config.ts         # 库构建配置（ES + UMD + d.ts）
│   └── package.json
└── docs/                      # 本文档站（VitePress）
```

## 设计原则

1. **样式即接口**：任何组件的视觉都可以只通过 CSS 变量覆盖，不鼓励使用 `!important` 或深层选择器。
2. **移动端优先**：组件默认尺寸、点击反馈、安全区都按手机场景设计，桌面端可通过 `ConfigProvider` 或媒体查询放大。
3. **渐进增强**：动画、毛玻璃、手势都是增强项，关闭后组件依然完整可用。
4. **不隐藏复杂度**：表单校验、弹层层级、滚动锁定这些容易出错的部分，库内部统一处理，但保留 `beforeClose`、`zIndex` 等逃生出口。

## 名字的由来

Vela 是船帆座，也是拉丁语中「帆」的意思。帆的形态决定了航向，正如主题系统决定了组件库的气质。
